# Rule

Understand enough. Decide enough. Build. Test. Update docs.

## Mode

- FULL: new app/module/architecture
- DELTA: material change
- EXECUTE: approved ticket/bug

## Before Build

1. Read repo.
2. Do not ask answered questions.
3. State known/unknown/blockers.
4. Ask only questions that change scope, workflow, data, KPI, permission, API, security, UI, architecture, or acceptance.
5. Recommend answers.
6. Approve:
   `scope | users | flow | data | permission | API | UI | security | scale | skills | acceptance`
7. Then build.

## Skills

Use smallest stack. Max 8 active.

- Current signal: last30days
- Current docs: Context7
- Workflow: Superpowers OR gstack
- UI taste: Taste Skill OR Open Design
- Motion: Emil only when needed
- Browser: Playwright
- Memory: Claude Mem only for long projects
- Graph: Graphify only for complex repo
- Observer: Task Observer only for long projects

Do not install overlaps.

## UI

Avoid AI gradients, glow cards, sparkle, giant padding, fake charts.
Use neutral canvas, client colour, compact tables, filters, states, keyboard, accessibility.
Deep Plum `#53284F` = restrained builder signature only.

## Dashboard

Every KPI:
`meaning | formula | unit | FY/Q/Month | source | freshness | breakdown | drill-down | target`

## Build Rules

Always:
- server permissions
- validation
- states
- tests
- reconcile totals
- update docs

Ask:
- dependency
- schema
- auth
- integration
- deploy
- destructive action
- skill install

Never:
- invent rules
- expose secrets
- fake tests
- copy licensed code blindly
- install every skill

## Docs

Use bullets/tables. No essays.

- BRD ≤120 lines
- PRD ≤150
- FRD ≤180
- Architecture ≤180
- Security ≤120
- Frontend ≤150
- Handoff ≤40

Stop docs when build is safe.

## Delivery

`Inspect → Clarify → Decide → Plan → Build → Test → Review → Handoff`

Done:
`works | secure | edge states | tests | reconcile | accessible | docs | no critical defect`
