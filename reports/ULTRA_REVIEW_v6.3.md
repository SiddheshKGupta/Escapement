# Ultra Review — Escapement v6.3

## Review question

Does the repository now preserve:

```text
Low token usage
Deep domain and institutional judgement
Complete historical capability coverage
Use of skills at their strongest phase
Overlap control
Development focus
Runtime enforcement
```

## Judgement

**Yes, subject to the explicit distinction between built-in and external
capabilities.**

The repository now behaves as a capability orchestrator rather than a static
instruction document or a catalogue of impressive names.

## What changed from v6.2

### 1. Design became governed

`design-intelligence.md` is now a constitution rather than an optional
reference.

Design specialists are separated by role:

- UI/UX Pro Max: research and recommendations;
- Taste: art direction;
- frontend-design: implementation;
- Impeccable: verification and polish;
- Emil: motion;
- Open Design: optional workspace.

### 2. Overlap became semantic

The repository no longer treats overlap as only a shared category.

It distinguishes:

- baseline plus intensifier;
- substitute;
- complementary;
- sequential;
- reference-only;
- meta-observer.

Karpathy and Ponytail are the clearest example.

### 3. Fine-grained strengths became routable

External systems are decomposed into their strongest subskills.

Superpowers is not one broad capability. It contributes brainstorming,
writing-plans, TDD, subagent development, parallel dispatch, code review,
verification and branch finishing at different phases.

### 4. Major fallback gaps were closed

Native fallback skills now exist for:

- product specification;
- data engineering;
- data analysis;
- frontend implementation;
- quality engineering;
- AI-agent engineering;
- automation engineering;
- legal/compliance analysis;
- investment analysis;
- generic software implementation.

### 5. Token accounting became accurate

The previous cost model counted full native skill bodies inside the automatic
context even though the context pack contained only pointers.

v6.3 separates:

- automatic context;
- invoked skill context.

This permits multiple useful skills within a phase while preserving the
1,800-word automatic pack budget.

### 6. Trigger matching became safe

Term matching now uses complete words and phrases.

For example:

```text
test
```

can no longer match inside:

```text
investment
```

## What remains external

The repository does not silently install:

- Superpowers;
- Ponytail;
- UI/UX Pro Max;
- Taste;
- Impeccable;
- Emil;
- Agent Reach;
- Last30Days;

Their strengths are mapped and visible. Actual use requires the exact source,
licence, security and installation decision.

## Controlled open item

`skill-ui` remains preserved but unresolved because the exact source has not
been confirmed. It stays disabled rather than being deleted or misattributed.

## Final conclusion

Escapement v6.3 achieves the intended balance:

```text
Small automatic context
+
Many lifecycle capabilities
+
Explicit authority
+
Phase-specific strength
+
Domain research
+
Executable fallback skills
+
Tested overlap rules
```

The next architectural improvement should be driven by failed evaluations or a
real project gap, not by adding more names to the registry.
